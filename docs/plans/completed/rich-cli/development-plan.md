## Summary

Migrate every CLI surface of the GenomeClaw toolkit from `argparse + print + log.info` to a Typer + rich framework that renders snappily for human terminals and emits stable, schema-versioned JSON for AI agents. Six phases over ~10–15 days of focused work; each phase ships a coherent slice and never breaks any existing command invocation.

## Critical Invariants to Respect

- **INV-D001** Raw Genomic Files Are Source-of-Truth — the CLI is presentation-layer-only; it must not introduce any write path to `/mnt/genomeclaw/raw/` or `/mnt/genomeclaw/reference/`. Every existing orchestrator's invariants stay intact.
- **INV-D002** Raw Genomic Artifacts Are Host-Side Only — not affected; the CLI runs host-side and dispatches to host-side orchestrators.
- **INV-D003** Heavy Scratch Is Separated From Authoritative Outputs — not affected; the CLI doesn't allocate scratch.
- **INV-P001** Privacy Is the Default Operating Mode — the CLI introduces **zero new network egress**. No telemetry, no auto-update checks, no crash reporting, no remote schema fetches. This is a hard constraint enforced by a privacy-default test that exercises every migrated command under a mock that fails any outbound HTTP call.
- **INV-P002** Agent Egress Is Named, Minimal-Sufficient — the new `--json` mode is the *receive* surface for agents (the agent calls the CLI; not the other way around). Schemas are minimal-sufficient: no fields default into JSON output beyond what the command's documented contract requires.
- **INV-R001** Rebuildability — `--version` reports the toolkit version + image digest (when running in the container). Error envelopes include the version so a user can reproduce a failure.

## Proposed New Invariants

- **NEW `INV-Cxxx` (provisional, name TBD): CLI Output Contract Stability** — every `genomeclaw` subcommand provides a `--json` mode whose stdout payload conforms to a versioned schema. Stdout in `--json` mode is reserved for the structured result; stderr is for progress, log, and diagnostic output. Schema version is part of the payload; field additions are additive; renames/removals require a major-version bump + deprecation cycle. Promotion gated on: this plan's Phase 1 + Phase 2 landing cleanly, schemas documented under `docs/reference/cli-output-schemas.md`, privacy-safety-reviewer pass.

## Current State Analysis

### What exists today

- **Single argparse-based entry point** at [packages/toolkit/src/genomeclaw_toolkit/cli.py](../../../../packages/toolkit/src/genomeclaw_toolkit/cli.py:1). One `build_parser()` function, ~800 lines, with `_add_<cmd>` and `_run_<cmd>` functions per subcommand. Reasonably clean for argparse; not coherent enough to scale.
- **Eight subcommands** (post-Phase-4C.3): `fetch`, `ingest`, `normalize`, `annotate`, `materialize`, `pipeline`, `setup`, `eject`, `doctor`. Flat namespace.
- **Output discipline**: mixed.
  - `print(f"wrote {path}")` for success contract — used by `bin/genomeclaw-prep setup --fetch-all` to chain commands.
  - `print(f"genomeclaw-prep <cmd>: {exc}", file=sys.stderr)` for errors.
  - `log.info(...)` from orchestrators, configured via `cli._configure_logging()` to stderr.
- **No tab completion**.
- **No --json**.
- **No --quiet / --verbose** beyond what `log.info` provides.
- **Help text** is auto-generated by argparse — readable but not branded; no examples; no consistent style.
- **Doctor's --json mode** is the only structured output today, and it's hand-rolled.

### What's missing

| Gap | Today's behaviour | What good CLIs do |
|---|---|---|
| Subcommand groups | flat `genomeclaw-prep <verb>` | `genomeclaw <noun> <verb>` (gcloud-style) |
| `--json` output | only on `doctor` | every command, schema-versioned |
| Progress bars | per-line print every 2s | inline-redrawn bars |
| Tabular output | plain text columns | rich tables |
| Phase banners (pipeline) | `[INFO] === pipeline: ingest ===` | rich panels with borders / color |

| Destructive op confirmation | `--force` opt-in | confirmation prompt + `--yes` escape |
| Error envelope (JSON mode) | not applicable | `{error_type, message, details, suggested_actions}` |
| Startup speed | ~140 ms for `--help` | ≤200 ms even with the new framework |

## Solution Design

### Architectural seam

The toolkit becomes a two-layer Python package with strict module boundaries:

```
+----------------------------------------------+
|   _cli/  (Typer + rich; this plan's scope)   |
|                                              |
|   __init__.py    Top-level Typer app +       |
|                  global flag callback +      |
|                  exception → envelope        |
|                  conversion at the boundary  |
|   context.py     AppContext dataclass        |
|                  (output mode, verbosity,    |
|                  flags) carried through      |
|                  Typer's Context.obj         |
|   console.py     Rich Console singleton      |
|                  (lazy, override-able)       |
|   output.py      OutputMode + Verbosity      |
|                  enums; emit() dispatcher    |
|   errors.py      CliError envelope +         |
|                  exit-code mapping +         |
|                  suggested-actions plumbing  |
|   tool.py        ToolRunner Protocol +       |
|                  default subprocess runner   |
|                  (the seam for chaining      |
|                  external CLIs like bcftools)|
|   version.py     Version assembly            |
|   completion.py  Tab-completion subcommand   |
|                                              |
|   commands/      One module per group        |
|     host.py       host {doctor,setup,eject}  |
|     refs.py       refs {list,fetch,verify,…} |
|     runs.py       runs {list,show,current}   |
|     pipeline.py   pipeline {run,ingest,…}    |
|                                              |
|   renderers/     One module per group        |
|     host.py       rich + JSON renderers      |
|     refs.py       for the host commands      |
|     runs.py       …                          |
|     pipeline.py                              |
|                                              |
|   types/         TypedDicts, dataclasses,    |
|     events.py    Protocols. ProgressEvent,   |
|     payloads.py  CliEnvelope, ErrorEnvelope, |
|                  command-specific payload    |
|                  shapes.                     |
+--------------------+-------------------------+
                     |
                     v
+----------------------------------------------+
|   prep/  (orchestrators; unchanged in scope) |
|   - ingest, normalize, annotate, materialize |
|   - fetch, setup, eject                      |
|   - doctor                                   |
|   - subprocess wrappers (_bcftools, _vcfanno)|
+----------------------------------------------+
```

**Strict boundary rules**:

1. **`prep/` never imports from `_cli/`.** Enforced by a lint check (Phase 1).
2. **`_cli/` lazy-imports orchestrators.** Top-level `import genomeclaw_toolkit._cli` must not transitively import `duckdb`, `pysam`, or any other heavy dep. This is what keeps cold-start `--help` under 200 ms.
3. **`_cli/commands/<group>.py`** defines Typer commands; it does *not* contain rendering logic.
4. **`_cli/renderers/<group>.py`** defines rich + JSON renderers as `Protocol`-conformant callables. The command module imports the renderer; the renderer never imports the command.
5. **`_cli/tool.py`** defines `ToolRunner` Protocol for chaining downstream binaries (bcftools, vcfanno, vep, mosdepth, samtools, …). The default implementation is a thin `subprocess.run`-wrapper. Tests inject fakes via `AppContext.tool_runner`.
6. **Adding a new subcommand never requires touching `_cli/__init__.py`** — each `commands/*.py` module registers itself with the parent Typer app via a top-level `app.add_typer(...)` import side-effect, discovered by `_cli/__init__.py` via explicit imports (no magic).

The orchestrators (`prep/`) keep their existing function signatures. The `_cli/` layer is responsible for:

1. **Command structure** — Typer apps + nested groups; one module per group.
2. **Output rendering** — rich for human; structured JSON for agents; per-group renderer modules.
3. **Progress reporting** — `progress_callback` hook passed into orchestrators; rich's `Progress` consumes the callback in rich mode; NDJSON event emitter consumes it in JSON mode.
4. **Error envelopes** — orchestrator exceptions get caught at the CLI boundary and rendered into a consistent envelope. The boundary is exactly one place (`_cli/__init__.py`'s top-level callback).
5. **Confirmation prompts** — destructive ops prompt unless `--yes` or non-TTY-with-`--yes-required`.
6. **TTY detection** — auto-detected; overridable via `--force-color` / `--no-color`.
7. **Schema versioning** — JSON output carries `cli_output_schema_version`.
8. **Tool chaining** — `ToolRunner` Protocol abstracts subprocess invocation, version capture, stderr streaming. Future refactoring of `prep/_bcftools.py` etc. to adopt this protocol is a separate plan; the protocol itself lands here so the seam exists.

### Quality bar (enforced from Phase 1)

A **clean-slate rebuild** is also a clean-slate quality reset. Phase 1 sets the bar for everything downstream:

**Typing — `mypy --strict`**:
- Added as a dev dependency in Phase 1.
- Enabled against `src/genomeclaw_toolkit/_cli/` from Phase 1.
- `prep/` migrated phase-by-phase as each phase touches it.
- No `Any` in public function signatures without an inline `# justification:` comment.
- `Final` for module-level constants.
- `Protocol` for tool runners + renderers.
- `TypedDict` for JSON payload shapes where stability matters.
- `Self` (PEP 673) for fluent / builder return types.

**Linting — `ruff check` with strict rule set**:
```toml
[tool.ruff.lint]
select = [
    "E", "F",      # core errors
    "I",           # import order
    "UP",          # pyupgrade
    "B",           # bugbear
    "N",           # naming
    "D",           # pydocstyle
    "RET",         # return statement consistency
    "SIM",         # simplification
    "ARG",         # unused args
    "PTH",         # pathlib over os.path
    "TCH",         # type-checking imports
    "PERF",        # performance
    "RUF",         # ruff-specific
    "C4",          # comprehensions
    "PIE",         # misc
    "PT",          # pytest style
    "S",           # bandit security
    "ANN",         # annotation completeness
]
ignore = [
    "D203",        # one-blank-line-before-class (conflicts with D211)
    "D213",        # multi-line-summary-second-line (conflicts with D212)
    "ANN401",      # disallow Any — too restrictive; enforced by mypy strict instead
    "S603",        # subprocess-without-shell-equals-true — false-positive heavy
]

[tool.ruff.lint.pydocstyle]
convention = "google"

[tool.ruff.lint.per-file-ignores]
"tests/**" = ["D", "ANN", "S", "PT011"]  # tests get less docstring/annotation/security strictness
"src/genomeclaw_toolkit/prep/**" = ["D", "ANN"]  # legacy code; migrated phase-by-phase
```

The `per-file-ignores` for `prep/**` is a transition mechanism: as each phase touches a `prep/` module, that module's ignore comes off and the strict bars apply.

**Docstrings — Google style, pristine**:
- Every public module: one-line summary + paragraph describing purpose + invariants enforced (by `INV-xxx` ID).
- Every public class / function / method: one-line summary + `Args:` + `Returns:` + `Raises:` sections where applicable.
- No "TODO" docstrings.
- Tests are exempt (`D` ignored under `tests/`).
- Module-level constants don't need docstrings (one-line `# comment` is fine).

**Test quality**:
- Every test has a docstring explaining its intent (one line is fine).
- Invariant tests cite the `INV-xxx` ID in the test name or docstring.
- Fixtures are typed.
- No `Any` returns from fixtures used in typed tests.

**CI gates**:
- `uv run pytest -q` — full suite green.
- `uv run ruff check .` — strict rule set clean.
- `uv run ruff format --check .` — formatting clean.
- `uv run mypy src/genomeclaw_toolkit` — strict mode clean.
- All four must pass for a phase to be marked complete.

### Key Design Decisions

1. **Framework**: **Typer**. Type-hint-native; nested-app abstraction; built on Click underneath (mature dep chain); tab completion comes for free. *Resolves spec Q1.*

2. **Tool name**: **`genomeclaw` only**. `genomeclaw-prep` was deleted in Phase 1's clean-slate cutover (no deprecation cycle). Phase 8 grep-cleans any lingering references in docs / plans / agents. *Resolves spec Q2.*

3. **Subcommand groups**: **hierarchical from day one, flat names never shipped**. Hierarchical names (`refs`, `runs`, `pipeline`, `host`) are canonical from Phase 1; the original argparse-based `cli.py` (which used flat names) was deleted in Phase 1 outright. Phase 8 grep-cleans any flat-form invocations still referenced in docs / plans / agents. Vocabulary (`refs`, `runs`, `pipeline`, `host`) confirmed by project owner. *Resolves spec Q3.*

4. **Schema versioning**: **global `cli_output_schema_version`** in every JSON payload. Single number to track; major bumps for breaking changes; minor bumps for additive. *Resolves spec Q4.*

5. **Streaming output for long-running commands**: **NDJSON** — each line is one complete JSON object representing one event. Used by `pipeline run --json`, `refs fetch --all --json`. Stable, parseable, well-supported. *Resolves spec Q5.*

6. **Testing rich output without ANSI snapshot brittleness**: tests use `rich.console.Console(record=True, force_terminal=True)` to capture structured render output, then assert on cell content / column structure, never on byte-exact escape codes. *Resolves spec Q6.*

7. **`--debug` mode**: present; prints structured tracebacks. In `--json` mode, `--debug` adds a `traceback` field to the error envelope. Normal mode hides traceback and shows just `message` + `suggested_actions`. *Resolves spec Q7.*

8. **MVP plan paused; rich-cli ships completely first.** Phase 4C.4 is on hold. The fetcher correctness fixes from 4C.4 W1 + W1.5 (Content-Length verification, bgzip EOF marker check, resume-on-stall via Range, bounded retries) **shipped in rich-cli Phase 3** (2026-05-12). The remaining 4C.4 work (W2 doctor sweep, W3 re-fetch, W4 dbSNP rename, W5 pre-flight validator, W6 vcfanno stderr, W7 parity check) waits for MVP resume after rich-cli Phase 8 closes — though in practice W3 (re-fetching the 5 truncated gnomAD files) can resume after rich-cli Phase 4 ships, since that's when the re-fetch operation becomes observable enough to run with confidence. *Resolves spec Q8.*

### Output mode matrix

| User invocation | TTY? | `--json`? | `--quiet`? | What happens |
|---|---|---|---|---|
| `genomeclaw doctor` | yes | no | no | Rich-rendered table + colored status; progress bars where applicable |
| `genomeclaw doctor` | no (piped) | no | no | Plain text (no ANSI), no progress redraw, periodic frame updates |
| `genomeclaw doctor --json` | yes | yes | — | JSON to stdout; progress messages to stderr; exit code as documented |
| `genomeclaw doctor --json` | no | yes | — | Same as above; agent-friendly |
| `genomeclaw doctor --quiet` | yes | no | yes | Suppress non-essential output; only errors + final status |
| `genomeclaw doctor --json --quiet` | — | yes | yes | JSON on success; nothing else; non-zero exit on error |

Rules encoded in `_cli/output.py`:
- `--json` and `--quiet` are independent global flags.
- `--no-color` / `--force-color` override TTY-detection.
- Mode is resolved once at CLI entry; passed through to every subcommand via Typer's context.

### Exit code contract

| Code | Meaning | When it fires |
|---|---|---|
| `0` | success | The operation completed and its post-conditions hold. |
| `1` | runtime error | The operation tried and failed (e.g. `vcfanno` exited non-zero; a network operation died after retries). |
| `2` | usage error | Invalid CLI args or flag combination. Typer raises before the handler runs. |
| `3` | precondition error | A required input is missing (no reference data; no run dir; no CURRENT symlink). User can fix and retry. |
| `4` | data integrity error | A file failed validation (truncated bgzip, schema mismatch, contig mismatch). User must fix the data before retrying. |
| `130` | interrupted | `SIGINT` (Ctrl+C). Standard Unix convention. |

Documented in `_cli/errors.py` and tested in `test_cli_framework.py`.

- New `cli_output_schema_version: "1.0"` in every JSON payload.

2. **Fetcher correctness in `prep/fetch.py`**:
   - `TruncatedDownload` raised when the on-disk byte count is short of the server's `Content-Length`.
   - `IncompleteBgzip` (in `prep/_bgzip.py`) raised when a bgzip target's tail doesn't match `BGZF_EOF_MARKER`.
   - Resume-on-stall via `Range: bytes=<offset>-` with exponential backoff (capped at 30 s) and bounded retries (`max_resume_attempts=5` by default).
   - `DownloadStalled` after the retry budget is exhausted.
   - HTTP-200-on-`Range` fallback: server-ignores-Range path detected via response status; on-disk file truncated; restart from byte 0.
   - MD5 preserved across resumes by re-seeding the hasher from on-disk bytes before continuing.
   - `progress_callback: Callable[[ProgressEvent], None] | None` parameter plumbed through `fetch()` → `_fetch_one_file()` → `_stream_to_file()`.

## Open Risks & Follow-ups

- **Typer's `--install-completion` writes to user shell config** — convenience feature, but at odds with our principle of "the CLI doesn't modify state outside its bind-mounts unless explicitly asked." Decided in Phase 5: ship `genomeclaw completion <shell>` that *emits* the script to stdout; user pipes it manually. We do NOT ship a `--install-completion` flag that writes to `~/.bashrc` without explicit `--write-to-rc` opt-in.
- **`progress_callback` hook ergonomics across orchestrators** — three orchestrators (`fetch`, `ingest`, `annotate_vcfanno`) need to accept the callback. Each currently has its own progress-reporting style. Phase 3 may surface that a common `ProgressEvent` dataclass needs more fields than we predicted. Iterate via an `initial_findings.md` if it gets complex.
- **Subcommand-group renaming friction** — existing tests + docs + the shim all reference flat names. Phase 6 cleanup may take longer than estimated if the surface is wider than the search suggests. Mitigation: do the grep-replace early in Phase 6, before the deprecation warnings ship.
- **Typer + rich version drift** — both libraries evolve fast. Pin `typer ~= 0.12` and `rich ~= 13` in pyproject.toml; bump deliberately, not via uv-resolved-latest.
- **CI runtime increase** — adding 100+ tests will slow CI from ~1.4s to ~3–5s for the host suite. Acceptable; document the expectation.
- **Out-of-band shipping interactions** — if 4C.4 W6a ships before this plan starts, undo that work as Phase 1's first task (avoid two rich-integration patches). If 4C.4 W6a is dropped (per spec Q8 recommendation), Phase 1 absorbs its scope cleanly.
